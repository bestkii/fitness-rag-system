DECISION 01

为什么有两种检索器？

不是为了堆技术。合成基准里 Dense retrieval 更好；教材开发集里字符 TF-IDF 达到 100% page-range Hit@3，因此系统按评测选型。

DECISION 02

为什么不自动发布？

健康内容的来源与表述需要人工判断。产品状态机只允许 draft → approved → export，不提供 publish 动作。

DECISION 03

如何保护私有资料？

教材 PDF、OCR 文本、向量数据和审核数据库只保存在本地忽略目录，不进入公网检索或云端生成上下文。

    03 / EVALUATION
    技术选择由评测驱动，
    不是由流行词驱动。
    同一个项目中，两类语料的性质不同，因此使用不同检索方案。所有指标都标明了评测对象与不能推出的结论。

    指标解释边界
    合成语料指标衡量的是 topic-pair 检索相关性；教材指标衡量的是目标页范围能否进入 Top-3。它们都不等于答案质量、医学正确性或临床有效性。
    
    
    

    
    
      
    04 / OWNERSHIP & SCOPE
    我实际完成了什么，
    系统明确不做什么。
    
      
    
        
    MY IMPLEMENTATION
    工程实现
    • FastAPI API 与 Pydantic 输入验证
    • PubMed / Crossref 检索适配与来源策略
    • BGE + ChromaDB 与 TF-IDF 双检索方案
    • OCR 质量门、页码追踪与本地审核状态
    • 草稿状态机、引用检查和导出门
    • 37 项自动化测试与 release guard
    
        
    EXPLICIT BOUNDARIES
    诚实边界
    • 不是医疗诊断或临床验证系统
    • 学术摘要只是检索线索，仍需查看原文
    • 没有自动小红书发布与互动能力
    • 没有把私有教材发送给第三方服务
    • 尚未评测内容质量、成本、延迟和互动率
    • 合成 benchmark 不代表真实世界医学知识库
